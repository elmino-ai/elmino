# Agent 架构与生命周期规范

根 [AGENTS.md](../../AGENTS.md) 按任务范围加载本文件。这里维护 Agent 执行、持久化、事件与资源所有权的共同约束，适用于 `packages` 中的通用能力和使用这些能力的示例

调用方式见 [Agent 使用指南](../agent.md)、[Elmino 应用实例](../elmino.md)、[Server 与 SDK](../server-sdk.md)。SDK 控制与子任务的具体用法分别见 [SDK 运行控制](../sdk-control.md) 和 [子智能体](../subagents.md)

## 能力归属

- Agent 静态定义、Thread 上下文、Turn 执行事实和宿主应用配置分别维护，不把它们合并成一个可变全局对象
- `llm` 持有 `Request`、`Message`、`Part`、`Event`、`Usage` 和模型公共能力，不依赖 Runtime、Agent、数据库、Server 或 UI。厂商 SDK 与协议差异留在 `llm-openai`、`llm-anthropic` 等对应适配器中
- 内部工具调用使用 `args`，推理配置与内容统一使用 `reasoning`。`thinking` 等厂商原生字段只留在适配器或明确的 Provider 原生参数边界，不扩散到 Loop、Store 和 SDK 领域模型
- `sandbox` 定义文件、命令和执行环境契约，具体本机实现归 `sandbox-local`；`runtime` 组合线程所需执行资源，不负责创建数据库或加载产品配置
- `store` 定义 `RuntimeStore`、`BlobStore`、执行记录和持久化线程契约；SQLite 仓储与版本化迁移归 `store-sqlite`。基础入口不加载 Node 文件系统，本地 Blob 实现从 `@elmino/store/local` 接入
- `thread` 负责 Canonical 上下文、transcript、线程快照和领域事件投影；`loop` 负责单次执行切片中的模型采样、上下文与工具批次；`agent` 组合工具、Hooks、Loop、Thread 和 Runtime，不重复实现主循环
- `engine` 持有调度、控制器、子任务协调、运行恢复和终态结算。子智能体调度属于 Engine 内部能力，不为目录对称另建顶层子智能体包或第二套执行器
- `core` 通过 `defineElmino()` 管理 Agent、模型与工作区装配、共享 Engine 和存储配置租约；`server` 借用这个实例，拥有 HTTP、鉴权接入、事件回放和网络生命周期；`sdk` 只通过公开契约操作远端，不导入数据库或本机执行实现
- `protocol` 持有跨端 Schema、事件 JSON 与游标语法，领域类型复用实际拥有者；`api` 组合请求、响应与文档契约，不另存一份运行状态。具体事件定义与工厂继续归 `thread/events`
- 通用基础工具按真实复用归 `shared`，领域逻辑留在所属包。不要为迁移旧产品的目录或类名制造一次性包装、空目录或薄转发层

## 执行实体与冻结事实

- 执行层级统一为 `Thread -> Turn -> Step -> ToolInvocation`。Thread 保存会话上下文，Turn 是一次任务的执行实体，Step 是一次 Provider sampling，ToolInvocation 是一次工具调用。`run()` 等执行动词可以保留，实体类型、字段、事件、记录和路由统一采用对应领域名称
- 同线程继续聊天创建新的 Turn；审批或自定义交互恢复继续使用原 Turn。不得为恢复新建替代 Turn，也不得把引导消息当作一轮独立执行
- HTTP、本地应用与子任务通过 Engine 的统一入口接纳执行。后台 `submit()` 服务于已持久化的后台 Turn，不把它当作任意异步任务队列
- 同一线程的异步准备、排队、运行与结算必须受同一份入口预留和控制所有权约束。没有活跃模型协程不等于没有执行所有权，恢复和取消不能越过准备阶段或覆盖正在结算的事实
- 控制请求携带准确的 Agent、工作区、线程与 Turn 身份；读取持久记录后校验归属。不能因为旧请求失效就静默控制线程后来产生的新任务
- 系统生成的 opaque ID 使用 `@elmino/shared` 的 `createId(prefix)`。宿主 Agent、工作区和模型注册表的稳定语义键继续按所属契约处理；Provider 原生工具调用 ID 与由消息派生的确定性片段 ID 不机械改为系统 ID
- Turn 只使用一份 `{ config, adapter }` 形式的 `TurnModel`。`config` 保存可恢复的非敏感配置，凭据和厂商 SDK 实例留在适配器。请求中的 `modelId` 选择宿主注册模型，不传可执行模型实例或客户端凭据
- 原 Turn 的模型配置、Agent 快照、审批模式、子智能体模式和角色目录均是冻结执行事实。恢复按原快照重新注入凭据，不读取当前默认模型，不允许通过恢复请求切换模型或提高权限
- Elmino 的模型注册键应与工厂返回的 `config.id` 一致，动态模型目录按宿主工厂契约解析。不要照搬产品模型目录的 ID、账号配置文件或全局可调用模型单例

## 持久化与迁移

- `RuntimeStore` 是 Thread、Turn、Step、消息、工具调用和派生关系等运行事实的持久边界；`BlobStore` 保存附件、工具结果等内容。两者可分别替换，不把数据库实现或文件系统路径暴露到 Engine 和远程 SDK
- Canonical 上下文是模型可重放历史，transcript 是展示投影。提醒消息、可见输入与工具结果按各自契约写入，不用一份展示缓存代替模型历史，也不重复保存两套权威工具输出
- 运行和线程状态转换、交互消费、待执行工具收口及相关扩展状态在所属事务中统一提交。并发请求以事务内最新状态判断；失败应回滚，不叠加旁路集合或兜底状态冒充已提交事实
- 数据库事务不回滚外部文件或 Blob 写入。实现和测试必须明确这条边界，不向调用方承诺跨外部操作的原子回滚
- 同一数据目录共享 SqliteStore 时必须复用同一个 BlobStore 装配，关闭后才允许更换。使用 `sqliteStore()` 时，同一配置对象按引用计数共享租约；最后一个借用者释放后才关闭资源
- SQLite Schema 与版本化迁移归 `store-sqlite`，依赖版本由根 workspace catalog 统一管理。Schema 变化通过所属包的迁移生成入口产生增量迁移，迁移文件随 npm 包交付，不能启动时使用 `push` 代替已提交迁移
- 已生成迁移不手工修改；变更后使用 `pnpm --filter @elmino/store-sqlite db:check` 验证一致性，新增迁移使用该包的 `db:generate` 入口，并先加载对应 Drizzle 技能
- 未发布开发阶段不为内部运行结构保留旧字段、旧状态、双写或启动兼容分支；这不授权启动时自动清库。迁移失败必须保留原数据库并阻止对应 Store 打开，不自动重置迁移记录、清空业务表或改写迁移基线
- 用户长期资产的兼容与数据迁移仍需保留；宿主账号、认证、工作区目录和产品控制数据不属于 RuntimeStore 的可丢弃运行缓存。不能把“清理运行数据”扩大为删除宿主资产或项目源码

## Runtime、Sandbox 与上下文

- 宿主提供稳定工作区和 `ThreadLocation`，包含 `workspaceId`、`workspaceKind`、`workspaceRoot`、`dir`、`cwd`。执行资源按真实位置创建，文件与命令操作使用线程的 `cwd`，恢复不能静默改用终端当前目录
- 已有线程继续使用持久化的工作区和相对目录。Runtime 按线程复用时必须校验 Agent 与执行位置，不能把另一个 Agent 或目录的缓存资源交给当前请求
- 工作区的创建、发现与用户资产目录归宿主，读取已有运行事实不能因为项目物理目录缺失而擅自重建关联项目目录。无法执行时按恢复流程报告或结算，不切换到另一项目继续运行
- 工具通过当前执行上下文的 `sandbox` 和 `SandboxFiles` 访问执行资源，不在通用业务工具里直接读写宿主本机路径。Blob 持久化通过独立 `BlobStore` 边界，不照搬旧产品把所有文件都交给同一 Sandbox 的假设
- 本机 Shell 选择、环境加载与环境快照归 `local`；已创建 Runtime 使用自己的快照，宿主刷新环境不修改正在执行的线程资源。远程 Sandbox 可以省略本机环境，不反向依赖本机登录配置
- 文件与命令授权以 Sandbox 和工具实际契约为准。若需调整工作区外访问边界，先修改所属协议与实现，不在个别业务工具中零散补权限分支
- `systemPrompt` 保留 Agent 基础身份指令，运行态上下文通过 Loop 与 Hooks 按实际能力注入。不要把产品目录、账号、市场或界面状态硬编码进基础提示词
- `promptStable` 在当前执行切片首次模型请求时解析并冻结，`promptDynamic` 每次请求重新解析；它们只装配 system，不写入 Canonical 历史，不依赖跨恢复、重启或新 Turn 的去重缓存
- 上下文压缩阈值等内部策略默认值留在所属模块，没有实际宿主配置需求时不扩大 `defineLoop()` options 或公共出口
- `promptMessages` 追加持久化提醒，不生成可见 transcript；`processMessages` 只做模型上下文纯投影，不改写原始历史，保留 Canonical 消息 ID 与 Turn 归属，过滤工具调用时同时处理配对结果。采样、Token 统计与摘要使用同一投影边界
- Hook 只持有所属执行的能力。`onStarted` 返回的清理函数只释放当前 Turn 取得的资源；共享 Store、线程 Runtime 和宿主服务由其创建方关闭
- `collectState`、`resolveInteraction`、`settleState` 通过明确的扩展命名空间维护可恢复状态，不建立第二套 Thread 状态，也不为了尚未迁入的插件体系引入注册和 UI 分发

## 工具、审批与控制

- 工具输入在 LLM 工具边界按 Schema 校验。`beforeTool` 改写参数后仍需重新校验和授权，Hook 放行不能扩大 Sandbox 本身的权限
- `scope` 描述工具的实际作用范围，不等于强制每次审批。工具的 `approval` 与执行时的 `approvalMode` 共同决定普通审批流程，`fullAccess` 仍保留明确授予完整访问的语义
- 内置工具审批使用当前批次真实请求及允许决策，必须按 Provider `callId` 完整覆盖批次。批准、拒绝、编辑参数和人工提供结果分别结算，不把整批简单处理为一个布尔状态
- 恢复必须携带最后展示的准确交互身份。SDK 的 `ClientInteraction` 同时绑定 Agent、工作区、线程、Turn 与中断快照；服务端在事务中再验证 pending 状态和身份，不自动替换为最新审批
- 拒绝工具会把拒绝结果交回模型，模型仍可解释或选择其他办法；取消整个待交互任务使用独立的 Turn 取消路径，不伪造工具拒绝、不再次采样模型
- 待交互取消必须原子匹配最新 Turn 与当前 `interruptId`，清除交互并固定 `cancelled` 运行终态，结算未执行工具及 Canonical 结果。工具自身继续使用现有状态集合，不为整体取消新增无来源的工具状态
- 运行中引导只提交给指定活跃 Turn，在 Step 边界消费，不替换正在执行的工具，也不新建 Turn。已经开始结算或关闭引导接纳后，应明确拒绝，不能把输入转发给下一轮
- 活跃执行中断通过原控制器发出，并等待模型、工具与结算路径退出。自然完成与停止可能同时发生，最终结果以持久事实为准，不因客户端点击停止就覆盖已完成终态
- 临时通知与流式输出不是第二份终态来源。终态事件必须在对应数据库结算成功后发布，使用同一份结束时间与中断身份；通知失败不能回滚已固定的结果，也不能阻止必要的内部状态唤醒

## 子任务与重启恢复

- 子任务派生、队列、角色冻结和 Child Turn 生命周期统一归 AgentEngine。工具只通过 `subagentHostService` 等宿主契约访问控制面，不在 HTTP、SDK 或单个工具里重新创建子线程执行器
- 线程级派生关系和 Turn 级工具调用关系都必须持久化。一个父工具调用关联一个子 Turn，重试同一调用找回原任务，不创建新的子任务；不同任务使用不同工具调用身份
- 子任务控制只能面向当前父线程的直接子任务。一般并行任务、未来团队关系或独立应用 Agent 不借用父子派生关系表达不真实的所有权
- 根 Turn 开始时解析角色目录，子 Turn 保存完整角色快照。角色目录由内置角色或宿主指定来源提供，不默认读取旧产品用户目录；恢复、排队与历史展示都使用冻结快照
- 角色描述名称、说明、图标与提示词，不把角色当作权限过滤器。`proactive` 模式不意味着自动注册派生工具，也不承诺无限递归派生
- 取消根运行和直接子任务时复用 Engine 的统一协调与结算入口。删除或释放相关资源前，要等待已接纳任务和异步失败结算退出，避免迟到写入复活记录
- 工作区恢复先识别当前进程已拥有的准备、排队、运行和结算任务，不覆盖它们。失去控制器的 running 运行固定为系统中断，不凭历史状态再调用模型
- queued 根任务没有持久调度器，不能当作可重调度子任务处理。可恢复 queued 子任务按原位置与冻结模型重新提交；位置、模型或准备失败通过统一失败结算收口，不静默改目录或清库
- 持久的待交互中断在重启后仍是原 Turn 的交互。恢复模型、工具和状态只消费该交互一次，不因 Server 重建重复执行工具

## 事件、SDK 与状态所有权

- 运行事件采用框架 `RuntimeEvent`，厂商原始流只在模型适配器转换。可见思考来自模型真实输出，不由客户端生成替代内容
- Server 的每个业务调用分别校验契约和资源授权，批处理中的请求不能共用一次授权结果。静态 API 文档与运行数据分开，文档不包含宿主凭据；自定义 Hono 接口的身份权限由宿主负责
- 创建或恢复接口返回接纳后的线程快照，不代表任务结束。HTTP 请求结束、断开 SSE 或关闭一个 Server 不自动停止共享 Engine 中的任务
- SDK 按 Client、会话、执行句柄、事件连接和线程投影等框架无关职责组织。根出口显式导出公开方法涉及的具名输入、结果与回调类型，内部连接队列和投影实现不因测试读取而扩大 API
- `ClientThread` 固定 Agent、工作区与线程身份，`ClientRun` 固定一次创建、恢复或观察的 Turn 身份。控制操作不从可变的全局“当前任务”重新选择目标
- `client.run()`、`thread.run()`、`start()`、`resume()` 与 `attach()` 复用同一观察与完成判定逻辑，不保留互相竞争的远程执行器。`attach()` 只观察既有任务，不重发创建请求
- SDK 不因连接失败、请求结果不明或本地超时自动重试提交。身份在提交前可保存，重新进入时通过 `get()`、`attach()` 查询原任务，避免产生重复执行
- `signal`、`detach()` 和取消订阅只结束本地观察，不隐式控制远端。远端活跃任务使用 `interrupt()`，待交互整任务取消使用 `cancel()`；每个观察者只释放自己拥有的订阅
- 会话持有引用稳定的统一投影，`getSnapshot()` / `subscribe()` 供框架外消费者与 React 共同读取；`watch()` 支持异步消费。消息、Turn、工具和 runtime 按服务端事实合并，不另外维护全局活跃任务、待审批和历史副本
- `Composer` 只拥有固定会话的草稿、提交接纳和本地队列。React 子入口只通过 `useSyncExternalStore` 绑定既有会话 / Composer；Query 子入口直接使用 oRPC utilities。基础 SDK 安装与导入不要求 React 或 Query
- 普通读取、观察者初始化与过载校准只合并快照，不能清除其他观察者的流式锚点；同一次真实传输重置共享一个边界，线程只重置一次
- 同一 Client 的高级会话观察共享所属 Agent / 工作区的事件连接，各观察者有独立的有界处理队列。异步监听器可以等待同工作区的运行或审批，不应堵住自己的事件来源；过载时用权威快照校准，不无限积累事件
- 高层正文、思考与工具回调按目标 Turn 处理，恢复先建立原内容基线，避免重复展示恢复前内容。同一 Turn 多次交互时，历史 `turn.interrupted` 不能提前结束后一次恢复
- 独立 `client.subscribe()` 按事件处理成功后确认游标，处理失败时允许重投递。高级会话连接因积压转为快照补齐时，不承诺 `onEvent` 逐条交付，也不伪造原始事件
- Server 重建或回放窗口不足时通过 `stream.reset` 触发持久快照重建。SDK 去重与流式合并只服务观察，执行是否完成、审批是否仍有效和结果内容仍以 Store 的权威事实为准
- 未读标记归运行存储中的线程事实，不在 SDK 或应用复制一套本地未读集合。历史按完整 Turn 分页；尚未提供的清除未读、线程重命名、归档、删除或线程列表游标，不写成已有 API 或用临时客户端状态冒充服务端实现

## 关闭与资源所有权

- 创建方关闭自己拥有的资源。单次 `runAgent()` 创建的 Engine 与借用租约随调用结束释放；长期 Elmino 实例在执行、观察和资源解析结束后释放自己持有的配置租约
- 直接传入的 RuntimeStore 实例和动态工作区工厂返回的 Store 仍由宿主关闭；固定工作区配置使用 `sqliteStore()` 借用时由 Elmino 释放租约。不能让某个 Turn、Hook 或网络接入关闭宿主共享存储
- Engine 关闭先让已接纳任务完成中断与结算，再关闭队列和线程 Runtime。不能先释放 Store 后等待迟到的模型、工具和结算协程
- Server 关闭新请求入口、自己的事件订阅与监听，等待已进入的请求结束，但不关闭借用的 Elmino。一个 Elmino 可接入多个 Server，关闭其中一个不影响其他接入和本地执行
- 整个宿主退出时分别发起 Server 与 Elmino 关闭，必要时并行等待，让 Engine 取消解除尚未结束的请求；汇总清理失败，不因第一个异常跳过其他资源
- `start()` 的默认退出信号处理只负责 Server。宿主统一管理应用时使用 `shutdownSignals: false` 并自行协调退出；嵌入外部 HTTP 服务时，宿主还要关闭自己拥有的监听与连接
- 关闭方法应幂等，关闭开始后拒绝新的执行与资源装配。取消观察不等于执行已结算，释放长期资源前仍需等待所属 Engine 和应用生命周期真正结束
