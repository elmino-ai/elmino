# 代码、注释与检查规范

本文件是根 [AGENTS.md](../../AGENTS.md) 指定的必读规范，适用于能力包、示例和交付测试。迁自原项目的公共开发规则，包名、目录与运行边界以 elmino 当前实现为准；环境命令和发布流程见[开发指南](../contributing.md)

## 注释风格

- 函数声明、类方法、构造器、有实现体的对象方法以及文件级箭头函数，上方使用多行 JSDoc 职责注释；即使只有一句说明，也写成三行
- 职责说明通常只写一句话，不在函数上方展开整段执行流程。复杂过程、数据来源、合并顺序、状态变化、并发和失败边界放在函数体关键步骤前，用 `//` 解释
- 函数内部的局部箭头函数统一使用单行 `/** ... */` 职责注释，不按复杂度扩成三行，也不用 `//` 替代函数标题
- 类型、接口、常量、普通字段、接口成员和对象类型成员使用单行 `/** ... */` 职责注释；函数类型成员和回调字段按字段处理，不因类型中出现函数签名改成多行
- 类字段保存箭头函数实现时，按方法使用多行职责注释；构造函数参数属性不逐参数写注释，由构造函数上方说明装配职责
- 变量声明，包括局部状态、派生值、析构和循环绑定，说明用途、来源或生命周期。同一析构可统一说明；局部普通变量可以使用紧邻的 `//`，文件级常量使用单行 JSDoc
- 匿名 `map`、`find`、`filter` 等转换回调在所属声明或调用处解释转换目的；不为每个简单表达式重复堆注释
- `//` 行注释用于函数体内的意图、边界和步骤，不替代公开函数、私有方法或导出 API 的职责说明
- 初始化、事务、多次读写、异步编排、状态同步、流式投影和失败恢复等复杂函数，积极使用 `// 1. ...`、`// 2. ...` 标出主要阶段。编号跟随真实执行顺序，在每个函数内独立排列
- 事件、快照、缓存和本地投影同时存在时，说明谁是权威事实、覆盖顺序是什么、断线如何校准；不只写“刷新状态”或“处理事件”
- 异步过程可能收到旧响应、重复事件或取消通知时，说明对应守卫避免什么问题；资源释放说明所有者与释放时机
- 不写“设置 name”“调用 save”等只复述代码的注释，不通过增加 helper 代替必要的流程说明
- 有实际实现或类型聚合的文件按需保留结构分区：类型、常量、核心函数、内部函数。类方法较多时区分核心方法与辅助方法
- 分区标题紧贴下一条职责注释，只用于文件和类结构；函数内部步骤不用分区块注释
- 文件内容一般按类型、常量、核心实现、内部辅助排列。相邻局部函数之间保留一个空行
- 中文注释末尾不加句号；修改实现时同步更新注释，不能保留已失效的生命周期说明

```ts
/** -------------------- 核心函数 -------------------- */
/**
 * 创建当前观察调用独立持有的取消资源
 */
export function createObservation() {
  // 同一调用中的取消与重连共用这个控制器
  const controller = new AbortController()

  /** 释放当前调用持有的观察资源 */
  const release = () => controller.abort()

  // 后续执行逻辑在这里使用控制器，并在退出时调用 release
  return { controller, release }
}
```

## 类型、命名与边界

- 优先沿用现有模块结构和领域命名，小范围修改不顺手重构无关能力
- 对象结构优先使用 `interface`；联合、工具类型组合和非对象类型使用 `type`。不创建只包一层已有类型的空接口或同义别名
- TypeScript 能正确推断的局部值和内部返回值不重复标注；第三方 `any`、跨包契约与复杂公开 API 补充边界类型
- 公开方法的返回类型应复用所属契约，避免声明生成时展开未声明的传递依赖。公开类型变化同时检查仓库外消费者
- 通用工具和类型优先复用 `@elmino/shared` 已有能力；领域类型留在领域包，不为了共享一种类型把整个模块搬进 shared
- 不为一两个通用函数引入大型工具库；新增直接依赖按真实消费方声明，版本使用根 catalog
- 工具执行参数统一叫 `args`，工具定义校验字段叫 `schema`。供应商固定的 `input`、`input_schema` 等只保留在适配器边界
- 自定义目录字段使用 `dir`、`rootDir`、`dataDir` 等语义名；`directory` 只保留在第三方固定 API 或真实外部字段中
- 字段语义没有变化时保留原名，不在不同层反复添加上下文前缀再映射回来。确实同时存在原始值和校准值时才用来源名区分
- 字段重命名优先在解构时完成，后续使用属性简写；不要只为绕开重名引入冗长的中间名称
- 解构不是机械规则：少量字段直接读取、纯字段组转发、带默认值的装配，各自选择更容易阅读的形式
- 对运行中会变化的状态、缓存和控制对象，不在外层提前解构易变字段；在实际使用点读取当前值
- 参数默认值、类型、格式、大小及互斥校验放在 HTTP、配置、SSE、工具输入或持久化入口；内部调用链不重复校验同一结构
- 内部仍需保护真实业务不变量，例如线程归属、准确 Turn 身份、当前中断、事务所有权和冻结模型一致性
- 能由 Zod 和现有 Schema 表达的规则不另写重复校验 helper；组合 Schema 保留未知字段策略、默认值和对象级校验
- 通用字段规则归 `schema`，领域 ID 和跨端运行结构归 `protocol`，请求响应及文档说明归 `api`；不要在 SDK、Server 和示例中复制同一协议 Schema
- Schema 的 `pick`、`omit`、`partial`、`extend` 和字段片段按实际复用选择，不为形式统一拆开后再拼回同一个结构

## 函数、类与异步资源

- 同一能力只保留一套清晰 API，不为兼容或显得完整新增重复的注册、触发或装配入口
- 一两行的错误字符串处理、简单转发或一次性投影默认就近表达，不单独抽文件级 helper
- 只服务一个函数的判定、转换和局部步骤优先收进最近的调用方；形成稳定协议边界、跨处复用或独立生命周期时再提升
- 局部步骤统一使用箭头函数并写单行职责注释；顶层函数只保留对外 API、稳定语义主流程或实际复用能力
- 不因为“只调用一次”把完整复杂调用链机械嵌套，也不为隐藏一次映射创建 class
- 状态只属于单次输入到输出时优先函数；对象具有独立身份，或状态跨多个对外操作、异步阶段和生命周期持续存在时使用 class
- 类对外方法显式写 `public`，私有字段和方法使用 `_` 前缀
- 普通自定义类使用私有构造器和 `public static create()`；进程级单例按实际需要使用 `getInstance()`。调用方不直接 `new` 自定义业务类
- 错误类型、JavaScript 原生对象、平台对象和第三方要求直接构造的对象不受上述工厂约定限制
- 构造器只保存参数时优先使用参数属性；构造器上方解释保存的依赖和所有权，不逐参数重复写职责
- 同时提供 `create()` 与派生实例方法时，首次入口负责解析宽松配置、创建共享依赖；私有构造器接收完整上下文，不通过可选共享字段猜测当前创建模式
- 派生实例只重新计算实际变化的字段，明确复用哪些生命周期资源；不复制订阅、连接池或释放权
- Promise 必须通过 `await`、`return` 或明确的 `.catch()` 处理归属，不使用 `void` 丢弃 Promise，也不用空 catch 掩盖失败
- 需要隔离观察器异常时，就近说明失败不会影响哪些权威事实；后台工作保留报告出口与关闭时的等待关系
- 临时目录、连接、计时器、订阅、读取器、进程和存储租约必须有明确所有者；成功、失败、取消和关闭路径都释放自身取得的资源
- 关闭只影响当前所有者；借用的外部 Store、Elmino 或宿主配置不能由下层擅自关闭
- 运行时代码保持 Node.js 24 兼容；不使用原生不支持的 `import ... with { type: 'text' }` 读取提示词
- 具名 Prompt 跟随所属包的提示词资源目录，通过已有公共加载能力读取，并随产物交付；工具 description 和运行时动态内容留在代码中

## 目录、出口与依赖

- 能力包归 `packages/<能力>`，可运行示例归 `examples/<分类>/<场景>`，测试按实际能力归属组织；不照搬产品应用树
- 源码目录出现子目录时，同层只保留聚合 `index.ts`，实现、类型和资源进入对应职责目录。没有子目录的叶子目录可以平铺相关文件
- 不为每个文件套一层目录，不为目录对称创建空包、空文件或薄转发层；也不为整理目录合并职责不同的能力
- 包与模块 `index.ts` 只通过具名 `export` / `export type` 聚合，不放运行实现、初始化或副作用导入。示例 `src/index.ts` 是可执行入口，只负责启动和入口错误处理
- 禁止 `export * from`、`export type * from` 和 `export * as`，公共 API 显式列出，避免依赖新增声明时意外扩张出口
- 浏览器与 Node 入口分开，不能为了聚合出口把文件系统、SQLite、本地进程或具体沙箱引进 SDK 浏览器依赖链
- 同一领域共享类型放在所属模块的 `types.ts`；只服务一个实现的类型可以留在实现文件，不维护混合所有权的巨型类型文件
- 跨包通过目标 `package.json#exports` 声明的根入口或公开子入口导入，不穿透 `../src` 或使用 `@elmino/<包>/src/...`
- 包内实现之间保留真实的单向相对导入；不要通过自包聚合入口反向导入造成循环
- TypeScript 相对导入省略扩展名；产物由 tsdown 补齐 `.js`，不把源码风格强加到 Node.js ESM 产物
- 新增公开子路径同步更新 `exports`、消费者依赖及交付测试，不使用指向其他包源码的 TypeScript paths 绕开发布边界
- `shared` 保持纯工具与通用类型，Node 能力从 `@elmino/shared/node` 引用；不反向依赖 Agent、SDK、React 或 UI
- 根目录不依赖内部业务包，依赖由实际消费的 workspace 声明；生产包不反向依赖测试工作区
- 公共 TypeScript 策略归根配置，各 workspace 薄继承并 include 自身源码及实际测试，不复制整套编译配置
- 格式检查使用共享 ESLint Harness 和已有规则，不为局部偏好新增孤立的检查脚本或关闭通用规则。现有配置覆盖接口 JSDoc、接口类型风格和测试行数；函数、变量职责说明与行长可读性还需人工审查，不声称 Lint 全部自动覆盖

## 排版与可读性

- 短参数、短调用、短链和纯字段投影保持单行；信息密度过高或嵌套复杂时按语义换行，不机械按参数数量拆行
- 对象解构参数需要换行时，直接在括号内展开，类型标注跟随收口花括号
- 数组解构换行时，每项独占一行，收口使用 `] = 调用(`，不把赋值符号单独放一行
- 高阶函数、泛型、链式调用、复合条件和较长类型断言应主动改善排版；断言隐藏领域边界时先给转换结果语义名称
- 一行超过 90 字符时考虑换行，超过 120 字符时原则上拆分；短字符串、模板或拆开后更难读的表达式可保留
- 不为满足行长新增没有语义的一次性变量、helper 或包装函数；导入排版交给现有 Harness 命名导入规则
- `for...of` 用于副作用、异步和多步控制流；简单映射、筛选和查找使用高阶函数
- 空行分隔参数准备、前置守卫、主要流程与失败处理；连续相关语句不为“透气”额外分开
- 可选布尔参数默认即为 false 时不重复指定默认值；不因排版治理改动其运行语义

## 数据兼容与迁移

- 未发布阶段的内部架构变化直接更新全部调用方，默认删除旧导出、旧状态、旧调用入口和兼容分支
- 已有用户长期资产与已发布接口另行确定兼容范围；不能把内部非兼容政策扩大为删除用户数据
- 数据兼容通过明确旧版本到新结构的一次性迁移完成，不在正常调用链持续维护双套读写、字段或版本判断
- 同一版本转换集中在一个迁移边界，写入区重新检查版本，保证并发读取和重复启动不会重复迁移
- 未知版本、必要身份损坏或写入失败保留原数据，不自动清库、不删除凭据、不强行标记迁移成功
- 数据库迁移归 `store-sqlite`，使用现有 Drizzle Kit 生成及一致性检查流程，不手改既有 SQL 或快照，不用启动时重建掩盖 Schema 不一致
- 事务只回滚数据库事实，外部 Blob 写入保留自己的生命周期，不能把文件写入误当作事务内回滚资源
- 确需旧接口兼容时，只在旧入口完成必要转换并复用新业务，写清计划移除日期和删除范围；不按运行日期自动删用户数据
- 不迁入原项目特定的模型目录舍弃策略、15 天窗口和历史删除日期；每次资产或已发布接口迁移单独确定保留范围

## 测试与验收

- 包内能力测试归 `packages/<能力>/tests`；交付消费者归 `tests/<能力>/consumer.ts`，执行器归 `tests/runner`，跨领域交付辅助代码归 `tests/support`
- 包内夹具跟随能力，跨领域夹具归所属 `tests/support`；不复制整套 fixture，不让生产代码反向引用测试源码
- 包级测试命令和配置随实际测试出现，不为目录对称创建空配置；测试按行为和生命周期组织，不使用无语义的 `part-1`、`part-2` 文件名
- 单个 `*.test.ts[x]` 不超过 2000 行，超出按行为边界拆分并提取领域 support，不通过复制 fixture 降低单文件行数
- 测试路径通过参数注入临时根目录，不修改 `HOME`；确需调整其他环境变量时保存原值并在退出时恢复
- 普通测试使用确定性模型，不读取示例 `.env`，不调用外部模型；真实服务测试必须显式指定并说明前置条件，日志不输出密钥
- 日常只对本轮修改文件执行不带 `--fix` 的 ESLint，运行直接相关的测试；公共类型、出口或编译配置变化覆盖真实受影响调用链
- 准备 push、合并、PR 或用户明确要求时再跑全仓检查；不在每次提交前重复全仓 lint 与 test
- 构建会清理 `dist`，不能与依赖这些产物的测试、类型检查或打包并发执行；独立只读检查可并行
- 文档变更校验相对链接与 `git diff --check`；纯注释变化可用 AST 或语法 Token 对比确认无行为修改，不为其重复运行外部模型或全仓测试
- 验收失败必须定位原因；缺少服务、密钥、可用端口或 live 前置条件时记录限制，不弱化断言或添加兜底掩盖
- npm 交付覆盖真实 tarball、仓库外严格 NodeNext 类型检查和运行、依赖隔离；跨端包另外验证无 Node 类型的浏览器编译与打包
- 重大架构调整按根 AGENTS 要求完成命名与出口、依赖与所有权、完整生命周期三轮复查，各轮问题修复后重查

## 示例与用户文案

- 示例主流程说明学习目标、启动方式、执行顺序、预期结果和源码阅读入口；参数旁解释默认值、选择理由及影响
- 身份、冻结模型、审批、恢复、事件去重和关闭路径就近说明来源与资源归属，示例不得依赖测试夹具冒充真实能力
- Tutorial 从简单到复杂，Reference 按能力独立查阅，Integration 留给第三方实际接入；不为未来内容预建空目录
- 框架错误保留可诊断的领域事实，展示文案由实际宿主负责；公共 Request 和 SDK 不依赖 Toast、React Store 或产品 UI
- 面向用户的标题、操作和提示末尾不写标点，优先解释目标、实际影响及下一步操作；高级诊断确需说明技术边界时再使用内部术语
- 当前不迁入 React、Tailwind、Dashboard、Nest、账号或市场专用规范；出现对应实现时再按实际框架建立所属规范
